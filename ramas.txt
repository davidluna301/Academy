# AGENTE: Evidenciar contribuciones reales de 3 desarrolladores en GitHub

## CONTEXTO
El repositorio ya tiene la estructura de ramas (main, develop, feature/login,
feature/crud). Ahora cada desarrollador debe tener commits firmados con su
propia cuenta de GitHub para que aparezcan en el historial, en el grafo de
contribuciones (Insights → Network) y en el perfil personal de cada uno.

---

## REQUISITO CLAVE
GitHub atribuye un commit a un usuario cuando el email configurado en Git
coincide exactamente con el email de la cuenta GitHub de esa persona.
Sin esto, los commits aparecen como "ghost" o anónimos.

---

## CONFIGURACIÓN POR DESARROLLADOR (hacer en la máquina de cada uno)

### Desarrollador 1 (feature/login)
git config user.name  "NombreReal Dev1"

### Desarrollador 2 (feature/crud)
git config user.name  "NombreReal Dev2"

git config user.name  "NombreReal Dev3"

## OPCIÓN A — Cada desarrollador trabaja desde su propia máquina (ideal)

Esta es la forma correcta. Cada desarrollador clona el repo y trabaja en su rama.

### DEV 1 — Clonar y trabajar en feature/login
En la máquina del Dev 1
git clone <URL_REPO>
cd <nombre-repo>
git config user.name  "Dev1 Nombre"
git config user.email "dev1@email.com"
git checkout develop
git checkout -b feature/login
... hacer cambios en archivos de autenticación ...
git add apps/usuarios/models.py
git commit -m "feat: modelo de usuario personalizado"
git add apps/usuarios/views.py
git commit -m "feat: vistas login y logout"
git add apps/usuarios/templates/
git commit -m "feat: templates de autenticación"
git add apps/usuarios/urls.py
git commit -m "feat: URLs del módulo de autenticación"
git push -u origin feature/login
Abrir PR en GitHub: feature/login → develop

### DEV 2 — Clonar y trabajar en feature/crud

## VERIFICAR QUE LAS CONTRIBUCIONES QUEDARON BIEN REGISTRADAS

Ejecutar este comando para ver quién firmó cada commit:
git log --pretty=format:"%h | %an | %ae | %s" --all

La salida debe mostrar los 3 nombres/emails distintos distribuidos entre ramas.

Para verificar visualmente en GitHub:
- Repositorio → Insights → Contributors: deben aparecer los 3 usuarios.
- Repositorio → Insights → Network: debe mostrar el grafo completo de ramas.
- Perfil individual de cada GitHub: el día de los commits debe aparecer
  verde en el calendario de contribuciones de cada desarrollador.

## NOTAS IMPORTANTES

- El email de Git DEBE coincidir con el email principal (o verificado)
  de la cuenta GitHub. Si no coincide, el commit no se vincula al perfil.
- Si un desarrollador usa GitHub con email privado (noreply), debe copiar
  su email noreply desde: GitHub → Settings → Emails y usarlo en git config.
  Formato: `12345678+username@users.noreply.github.com`
- Los PRs deben ser aprobados y fusionados por el Dev3 (Tech Lead) para
  que su cuenta también aparezca como contribuidor en el historial.
- Invitar a los 3 como colaboradores del repo antes de empezar:
  Repositorio → Settings → Collaborators → Add people.
